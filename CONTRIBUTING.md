# Contributing

Thanks for helping improve PocketOps!

1. Open an issue for bugs or proposals before substantial changes.
2. Keep pull requests focused and explain the user benefit.
3. Preserve local-first behavior. No telemetry, remote upload, account requirement or paid API in the core path without prior discussion.
4. Never include real personal documents, secrets or private data in tests, screenshots or issues.
5. Check desktop and mobile layouts; keep controls keyboard-accessible.
6. Update docs and tests when behavior changes.
7. Prefer small, reviewable pull requests.
